# M7 — Protocols: MCP client, ACP server, UTCP, A2A

**Status:** spec drafted (2026-10-26). Frontier 009 resolved by ADR-0016; the
interop boundary is recorded in ADR-0017.

## Scope

Ecosystem interop, inbound and outbound:

- **MCP client** — Orexis connects out to MCP servers (integrations).
- **ACP server** — editors and hosts connect in to Orexis as the agent.
- **UTCP client** — direct tool calls over HTTP/CLI/MCP from provider manuals.
- **A2A client** — Orexis calls remote agents (agent card, tasks).

Every protocol is a sans-io core plus thin I/O shells (invariant 14); the
JSON-RPC 2.0 envelope shared by MCP, ACP, and A2A lives in
`orexis-adapters-jsonrpc` (ADR-0005 mechanism, ADR-0017).

## MCP client

Port Kindred `mcp.rs` (stdio, dynamic discovery, tools/resources/prompts) as
a sans-io core; shells for stdio and streamable HTTP.

- Handshake: `initialize` with capabilities; `tools/list`, `tools/call`,
  `resources/read`, `prompts/get`; request/response correlation by id.
- Servers are configured per user/project (`.orexis/mcp/`, project wins);
  no shipped defaults.
- Connect at session start; tool specs register into the session; a failed
  server is a visible session event.
- Tool names are namespaced `mcp/<server>/<tool>`; calls pass the permission
  gate (default `ask`); output is delimited and capped; server tool
  descriptions are delimited in the prompt.

## ACP server

`orexis acp` (daemon-crate bin, wired through composition) speaks ACP over
stdio.

- `initialize` → capabilities; `session/new` → session; `session/prompt` →
  the turn loop; `session/update` → streaming deltas (say → message chunk,
  tool call → tool_call/update); approvals → `session/request_permission`;
  `session/cancel` → interrupt.
- `fs/read_text_file` / `fs/write_text_file` callbacks are served by
  Orexis's own workspace through the permission gate — one fs path.

## UTCP client

Port Kindred `utcp.rs` (manuals, call templates, `search_tools`/`find_tool`)
as a sans-io core.

- Manuals are user/project config like MCP servers.
- Transports: HTTP (`adapters-http`), CLI (through the sandboxed
  `ToolExecutor`), MCP (composing the M7 MCP client).
- Tool names are namespaced `utcp/<provider>/<tool>`; same gate, delimiting,
  and caps as MCP tools.

## A2A client

Client only (ADR-0017): agent card discovery, `message/send`, `tasks/get`,
SSE streaming where the peer supports it. HTTP shell over `adapters-http`.

## Integration rules (all external tools)

1. One tool surface: external tools dispatch through the existing
   `ToolExecutor` + permission gate; no second policy system.
2. Default permission `ask`; ruleset may allow per server/provider or per
   tool; the floor survives YOLO.
3. Untrusted content — tool output *and* tool descriptions — is delimited
   (invariant 22) and capped.
4. Deferred loading above ~15 tools applies uniformly (§7).

## Architecture

- `orexis-adapters-jsonrpc` — JSON-RPC 2.0 envelope, ndjson framing,
  correlation; pure, no I/O (ADR-0005 rules).
- `orexis-adapters-protocol-mcp` — sans-io core + stdio + streamable-HTTP
  shells.
- `orexis-adapters-protocol-acp` — sans-io dispatch + stdio shell.
- `orexis-adapters-protocol-utcp` — sans-io core + transport shells.
- `orexis-adapters-protocol-a2a` — sans-io client core + HTTP shell.
- `orexis` binaries: `acp` joins `serve` in the daemon crate until the
  `orexis` binary consolidation.
- `orexis-protocol` unchanged: daemon↔client only (ADR-0007).

## Does not ship

- MCP server (Orexis as an MCP server) — SDK/marketplace fog.
- A2A server — team-mode fog.
- MCP sampling, roots, elicitation — no harness in the corpus needs them.
- OAuth-protected MCP servers — auth-kind work follows ADR-0016's auth
  trigger.
- Shipped default MCP servers or UTCP manuals — supply-chain decision.

## Fog (after M7)

A2A/UTCP adoption — whether either is promoted beyond fixture-level into
default surfaces — is decided on M7's evidence, per the map's "not yet
specified" row.

## Gate

- [ ] Conformance fixtures per protocol, run against the sans-io cores with
      recorded transcripts (never live peers).
- [ ] `scripts/m7-gate.sh` green: fmt, clippy, boundaries, protocol suites.
- [ ] One real peer each, manual: a real stdio MCP server; an ACP client
      driving `orexis acp`; a UTCP manual against a real HTTP endpoint; an
      A2A sample agent.
