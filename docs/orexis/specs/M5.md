# M5 — The entity

**Status:** automated gate green (2026-10-26); manual `/self` and live model switch remain. Decision 007 resolved by ADR-0013.

## Scope

The persistent identity layer: an entity event log, six drives, PAD affect and
posture, a lexical memory lattice, and identity distillation. The entity is
sovereign local state; workers share it (invariant 18); it never mutates the
prompt mid-session.

## Model (ADR-0013)

- **Six drives:** connection, curiosity, mastery, coherence, rest, growth.
  Each is a slow pressure in `[0,1]` with baseline, decay, and satisfaction.
- **Affect:** PAD — valence, arousal, dominance, each in `[-1,1]`.
- **Posture:** turn-boundary execution parameters (model tier, thinking, repair
  budget, verification, risk appetite, exploration). Not a Strategy.
- **Invariants:** drives propose at boundaries; affect modulates posture;
  neither changes the prompt mid-session; affect may add caution but never
  weaken permissions; workers read posture, never mutate the entity.
- **Moods** are derived display labels, not stored state.

## Entity event log

The entity has its own append-only log, separate from session events:

- `EntityStart`, `DriveUpdate`, `AffectUpdate`, `DiaryAppend`, `TraitUpdate`,
  `MemoryWrite`, `MemoryForget`, `PostureChange`.
- SQLite with WAL, `seq` + ULID, JSON payloads, export/import JSONL.
- Projections (current drives, affect, traits, memories) are derived from the
  log; snapshots may cache them but the log is the source of truth.
- Entity state lives under the Orexis home; no telemetry.

## Memory lattice

Four kinds, all lexical:

| Kind | Holds | Written by |
|---|---|---|
| **Episodic** | What happened in a turn/session | Turn boundaries, recovery |
| **Semantic** | Facts and preferences about the user/repo | Reflection, user corrections |
| **Procedural** | How to do a recurring task | Successful patterns, skills |
| **Identity** | Trait evidence | Distillation |

Recall is lexical (tags, keywords, recency, confidence) and bounded. **No
embeddings, no vector RAG over code.**

## Identity distillation

- A **diary** is append-only; it records observations, decisions, and outcomes.
- **Traits** are distilled statements with `evidence: Vec<entity seq>`,
  confidence, and decay. A trait without evidence is not persisted.
- `IDENTITY.md` is generated from traits; never agent-authored as a source of
  truth. `SOUL.md` is not a thing.
- `/self` shows drives, PAD, moods, traits, and recent diary entries.

## Mid-session rule

At session start, the entity injects a bounded identity/context section. During
a session, drives/affect/posture may change routing and risk, and the entity log
may grow, but the **system prompt and context stay fixed**. Identity changes
take effect at the next session. This is the prompt-cache invariant and the
"identity never leaks mid-session" gate.

## Architecture

- `orexis-core`: entity types and pure updates (drives, PAD, posture, traits,
  memory records).
- `orexis-ports`: `EntityAppend`, `EntityRead`, `EntityFactory`, `MemoryRecall`.
- `orexis-usecases::entity`: pure drive/affect/posture/distillation logic.
- `orexis-adapters-entity-sqlite`: the entity log and projections.
- `orexis-composition`: wires the store; no adapter construction elsewhere.

## Gate

- [x] Identity never leaks mid-session: a trait added between turns does not
      enter the second prompt.
- [x] Every trait has evidence refs and confidence; decay is tested.
- [x] Entity state survives restart and shared handles. *(Live model switch is manual.)*
- [x] Export/import round-trips the entity log.
- [x] Lexical recall is bounded; no embeddings.
- [x] `scripts/m5-gate.sh` green (automated).
