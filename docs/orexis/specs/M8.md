# M8 — Team mode (opt-in): workers, strategies, board, bus, blackboard, scheduler

**Status:** spec drafted (2026-10-27). The domain decisions are recorded in
ADR-0020; §9's benchmark gate decides whether team mode ships or stays
experimental.

## Scope

The team domain, opt-in and benchmark-gated:

- **Workers** — in-process execution instances over their own sessions,
  sharing the entity's identity (invariant 18).
- **Strategies** — `plan`, `build`, `review`, `mine` as use-case
  definitions (invariant 16): prompt fragment, toolset filter, verify
  policy, budget defaults.
- **Board** — durable tasks with owner, required strategy, blocking edges.
- **Bus** — direct and room messages, persisted as events.
- **Blackboard** — shared workspace artifacts and leases.
- **Scheduler** — admits tasks under provider capacity, roster, and depth.
- **Supervisor** — stall detection, restart, escalation.

## Architecture

- `orexis-ports`: `BoardStore`, `MessageStore`, `ArtifactStore` (+ leases);
  `Provider` gains `capacity()` (invariant 17).
- `orexis-usecases`: `strategy` (definitions), `scheduler` (admission),
  `supervisor` (watchdog), `team` (the orchestration loop).
- `orexis-adapters-board-sqlite`, `orexis-adapters-message-sqlite`,
  `orexis-adapters-artifacts-fs` — following the session-sqlite pattern;
  constructed only in composition.
- The daemon orchestrates: team mode is a daemon concern (ADR-0006); the
  TUI/desktop fleet, board, and artifacts panels read the real domain when
  team mode is on (ADR-0012's contract), projections when off.
- One turn loop: workers run the existing `run_turn`; the team layer
  composes it, never duplicates it.

## Integration rules

1. Workers pass the same permission gate as sessions; a worker's toolset
   filter can only narrow, never widen (the floor survives YOLO).
2. Worker output to the board/bus/blackboard is untrusted content for the
   CONSUMING worker: delimited and capped like any tool output
   (invariant 22).
3. The entity's drives/affect see worker outcomes as session outcomes —
   one entity, many workers (invariant 18).
4. Budgets: per-worker step cap and wall clock; exhaustion fails the task
   visibly and posts to the bus.

## Limits (§9; profiles cap, teams tighten, never exceed)

| Limit | Value |
|---|---|
| Local provider generations | 1 |
| Remote concurrency | per provider profile (`capacity()`) |
| Roster size | 16 |
| Board tasks | 256 |
| Spawn depth | 1 (flat) |

## Does not ship

- A2A server (team-mode fog per ADR-0017).
- Remote workers; spawn depth > 1; roster > 16.
- A second permission system for teams.
- Team mode as the default (invariant 19).

## Gate

- [x] The automated suites: ports, adapters, scheduler, supervisor,
      orchestration.
- [x] `scripts/m8-gate.sh` green: fmt, clippy, boundaries, the M7 chain,
      the team suites.
- [x] The benchmark, measured: team does **not** beat serial on a breadth
      task at ≤2× tokens (≥15% pass rate or ≥25% wall-clock). It passes
      more pairs, but on one flipped pair and at ≈18× the wall clock, so
      team mode stays experimental and ships opt-in.
- [ ] Manual: a real team run on a real repository with the fleet panel
      showing live workers.

### Gate evidence (2026-10-28)

| Axis | Result |
|---|---|
| Paired breadth runs | 5 (3 public + 2 held-out), Qwen3.5-2B, llamacpp |
| Pass rate | serial 4/5 → team 5/5; mean diff +0.200, CI [+0.000, +0.600] |
| Wall clock | mean gain −1,720%, CI [−2,319%, −922%] |
| Tokens | 1.80× (inside the ≤2× budget) |
| Verdict | **experimental** |

The flipped pair is M8-16's listing trap: the serial model read
`.orexis/alpha.txt` and ended its session, so the team "won" the pair for
the wrong reason. Four of five team runs only finished because the driver
idled to the bench's 200 s cap. Details and the per-task table:
`.scratch/orexis/m8/M8-10-bench-gate.md`; data:
`bench-results-qwen35-gate.jsonl`.

The inspected team runs are not parallel work: the driver did the task
itself while the plan worker stalled on its first `board_add` — a worker's
approvals reach no client, so the hub's 300 s clock expires (M8-17). Until
that is fixed the gate cannot measure team mode; the wall column is the
approval timeout.
